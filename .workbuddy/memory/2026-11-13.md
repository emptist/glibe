## 06:06 — owner 追加类比：SwiftUI 的 POP；上段「卡点」按此更正

- owner 逐字：*「这跟SwiftUI的protocol oriented programming不是很像吗？
  gleam比他更纯粹更简单，你要理解之后才能做对。」*
- **理解**：Swift 的 protocol 先声明一组能力要求，类型遵守后才获得能力；
  Gleam **没有 protocol / typeclass**（core §1「absent FOREVER」），
  一个全标注的 `pub fn` 签名**本身就是**那条要求，`todo` 让它在零实现时
  就能编译，`case` 穷尽 + `|>` 形状约束（R41）替编译器做一致性检查，
  不需要 conformance / extension / associated type / existential。
  所以「框架」= 每个 type 周围的一整套 fn 签名，不是 type + 描述文档。
  leaf/branch 只有 type 无 fn = 只声明了值的形状，没声明能对它做什么。
