## 追加：owner 校正硬链接模型（撤回上面「实测断链」的措辞）
- owner 逐字：*"file link (ln without -s or anything else) should not be
  broken in a unix/linux filesystem. since it is basically a record of
  pointers to actual storage on disk filesystem, if it is so easy to break,
  then it is not linked."*
- 正确模型：inode 持有存储并计目录项数，`ln` 只是再加一个指向该 inode
  的名字；没有引用链、不可能悬空（只有 `ln -s` 才会 dangling）。所谓
  「断链」其实是**某个目录项被替换成新文件**：原文件在别的名字下仍完好，
  link count 减一。
- 实测（APFS）：`cp src <已存在硬链接>` 与 `> name` **保持 inode**
  （339900185 / link count 2 前后不变）；原子保存（临时+rename）、`mv`、
  `git checkout/restore` 才替换目录项。故把 `cp` 列为断链原因是错的；
  上一轮所说「SKILL.md 旧协议会诱导 AI 用 cp 破坏单一数据源」同样撤回。
- 结论：单一数据源是文件系统事实，不需要 cmp 门禁 / guard / 重建脚本；
  `cmp` 对同一 inode 恒真，真正的检查是 `stat -f '%i %l'`。git 存字节
  不存目录项，clone 后需重新 ln。
- `gits/gleam-language` README §1/§5/§6 与 01-01-PLAN 已按此改正、逐字
  引用 owner，提交 `5f1a798`（该仓库无 remote 故未 push），六条门禁全 0。
  `knowledge/SKILL.md` 的旧 copy/cmp 段是**过时描述、非风险**，仍未改。
