## Environment fact — WRONG, CORRECTED later the same day
First draft of this log said "no toolchain on this machine: `gleam`, `erl`, `mix` absent."
**That was false.** The user corrected it: they are installed via brew. The real problem
is that **WorkBuddy's sandboxed shell PATH omits `/opt/homebrew/bin`** — a normal macOS
shell has it, this agent's does not. Toolchain is complete and works:
`gleam 1.18.1`, `Erlang/OTP 29`, `Elixir 1.20.4`.
Fix: `export PATH="/opt/homebrew/bin:$PATH"` before any gleam/erl/mix command.

Lesson: when `command -v X` comes up empty, **search the filesystem before concluding X
is not installed**. An empty PATH result is not evidence about the machine. Landing the
wrong call here cost a whole review pass and turned three runtime facts into guesses.

Workarounds that were fine for reading-only, and are still valid:
- `build/packages/<dep>/src/<dep>@<mod>.erl` holds the real pinned stdlib source.
- `build/dev/erlang/glibe/ebin/*.beam` mtimes tell you *when* the project last built.
- Generated `build/dev/erlang/<pkg>/_gleam_artefacts/*.erl` gives the exact runtime tuple
  shape of a Gleam record (`-type data_bar() :: {data_bar, ...}`) — the reliable way to
  hand-build records for an Erlang driver.
