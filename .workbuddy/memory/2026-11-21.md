## Interval 是不是 type：编译探针（owner 提问，2026-11-21）
- **答：是。** `src/glibe/api/interval.gleam:47` 的 `pub type Interval { …九个 ctor… }` 是真
  custom type（名义类型），不是 String alias、不是值级 tag。owner 的
  `pub type Season { Spring Summer Autumn Winter }`（其笔误 Autom→Autumn）就是正确写法；
  Gleam 没有 `enum` 关键字，"enum" 只是 nullary-constructor custom type 的俗称，更一般是
  sum type（SourceBar 九变体带字段，`sourcebar.gleam:106-179`）。
- `/tmp/interval_probe` 实测（Gleam 1.19.2）：① 加第十 ctor → `Inexhaustive patterns`，
  missing: `IntervalOneDay`；② `a > b` → Type mismatch，`>` 只吃 Int（无 ordinal / 排序）；
  ③ `a.label()` → Unknown record field，编译器明说 "Gleam is not object oriented … use the
  function syntax"；④ 两个 ctor 完全相同的 custom types 互传 → Type mismatch。
- **更正旧 measured fact**：旧记忆写「qualified ctor patterns are a syntax error
  (Widget(_) not Event.Widget(_))」。实测 `event.Widget(x)`（**模块名**限定）合法，与
  `sourcebar.gleam:205-214` 的 `interval.IntervalOneHour` 一致；语法错的是
  `Event.Widget(x)`（拿**类型名**当限定符）。已同步 MEMORY.md。
- 与 C/Java enum 的差异：无 `.value` / ordinal / `values()` / 方法 / trait impl / 隐式 String
  转换。`to_string`/`from_string`（interval.gleam:88-117）是显式 codec；`all()`（:73-85）
  必须手写且新增 ctor 不会让它编译失败，靠 `test/config_test.gleam:17-20` 的 length 9 +
  round-trip 兜底。
- 二选一不因类型性改变：SourceBar variant 与 Interval **都是** custom type；owner 裁定的是
  权威来源（从 variant 读 interval：`sourcebar.interval(of:)` :203），gate 收
  `(Timeframe, SourceBar)`，Timeframe 无 interval field。
