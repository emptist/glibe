## 2. 三层 ownership（谁持有哪个值）

```
L3 边界 adapter  输入: SourceBar 到达 → Msg    视觉: SpecShape → renderer    耳口: 音频↔Msg
        │ on_event 归一         │ on_event 归一               │ on_event 归一
        ▼                       ▼                            ▼
L2 MVU (Dashboard)  Model = Desk（唯一）；Update(Msg, Desk)->#(Desk, Command)；
                    View(Desk) -> List(Node) 即 Dashboard 窗口（H：view 叫 Dashboard）
        │ 调用领域纯函数（不是调度器）
        ▼
L1 领域核（已有）  Desk → Broker → Instrument → Timeframe → leaf/branch，纯值重算（R33）
```

- **L1 领域核**（已存在，正在填 body）：`Desk` 是唯一 source of truth。任何重算都是
  `Desk -> Desk` 纯函数。**保持不变，本设计不动它。**
- **L2 MVU = Dashboard**（新设计；view 层名字按 H 用 Dashboard）：Elm 三段式，与 B 同构——
  - Model **不另存一份领域数据**，持有 / 引用 `Desk`（官方 guide 14：state 是纯数据结构、
    无进程无副作用无框架耦合，存进 model 在 update 里更新）。
  - 消息归一用官方 **`app.application(init, update, view, on_event)`**：`on_event: Event -> Msg`
    把 renderer 事件映射成应用自有 `Msg` 闭集（读书 3.2；比我上轮写法更准）。
  - `update(model, msg) -> #(model, Command(msg))` 调 L1 的读写对；它是**表现层事件循环，
    不是 R33 禁止的调度器**——领域重算仍是纯 `Desk -> Desk`。
  - `view(model) -> List(Node)` 返回顶层窗口（Dashboard），`[]` 干净退出（读书 3.1）。
  - **多窗口 ≠ 多 runtime（读书纠正 3.4）**：同一 app 的多窗口共享**一个** model/update/view，
    没有窗口管理器状态。多个 runtime 只对应**多 renderer / 多客户端**（guide 16 shared actor），
    不是"多开窗口"的理由。上轮"眼耳口各一 runtime"的表述据此作废。
  - **眼耳可分可合 = transport 选择（读书 3.5）**：model 一份在 BEAM，renderer 经
    Spawn / Stdio / Iostream(adapter) 接入；不必把眼耳做成两个各存领域数据的 app。
- **L3 边界 adapter**（新设计）：把外部世界归一成 `Msg`，把 `Desk` 投影成外部世界。
  - 输入：provider 原生形状 → 标准 `SourceBar` → `Msg`（R28 的 to_sourcebar 已是这条）。
  - 视觉：`View` 产 `SpecShape`（框架中立 IR）→ plushie `fusion` 翻译成节点 → renderer。
  - 耳口：STT（音频→指令 Msg）/ TTS（反馈 Msg→音频）；platform-native 依赖隔离在平台子包，
    core 保纯（speak_engl 的 domain/platform 分离）。

## 3. 从兄弟项目坑来的设计约束（每条带机制，不做装饰）

| 坑（来源） | 设计约束 / 机制 |
|---|---|
| 以为"多窗口要多个 runtime"（try_plushie §30.1 旧二手措辞；**读书纠正**：官方 composition-patterns 明说多窗口共享一个 model/update/view） | 多窗口共用一个 MVU；多 runtime 仅用于多 renderer/客户端（guide 16 shared actor）。写进 L2 模块 `////` |
| `receive` 必须在 Subject owner 进程，`command.task` 包一层就 panic 且被吞（speak_engl "一行改动，最大收益"） | 声控边界注明 owner 进程归属，不包 task；错误不静默吞 |
| `os:cmd` 要 charlist 不要 binary；atom 用 `create` 不是 `get`（glib 声控栈实测） | 归入平台子包的 FFI 边界，`@external(erlang, …)`，不手写 `.erl` |
| decode 形状先探针实测，别猜（glib 多处 errata） | 每个新 adapter 先探针再定 type |
| 重资源（whisper 模型）用 `persistent_term` 缓存省 ~500ms（speak_engl） | TTS/STT 边界按引用缓存，不复制进 model |
| 字号 0 崩 renderer；mock/headless 全绿但窗口起不来；`testing.click` 绕过真实 hit-test（try_plushie + 官方 guide 15） | 三后端测试 + 真窗口启动都算验收；测试绿 ≠ 窗口能跑，写进验收判据 |
| 手写 `.mjs` / JS target 是祸根；手写 `.erl` 静默编译（owner 08:16 / 探针） | 全程 erlang target、零手写 JS/erl；`@external` 只在边界 |
