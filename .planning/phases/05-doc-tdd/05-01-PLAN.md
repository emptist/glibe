## 2. 本轮做什么（少量如何做）

1. `git checkout -b doc-tdd`（就地，不 push）。
2. 旧 `src/`、`test/`、`scripts/`、`probes/`、根目录 review/session 笔记、
   `docs/` 里的补课笔记整体移入 `deprecated/2026-11-12-pre-doc-tdd/`。
   留 `RULINGS.md`、`STATE.md`、`PENDING_DECISIONS.md`、核心镜像。
3. **从零搭空架子**：每个模块的 `////` 点名本计划，`///` 覆盖每个 type 与 fn；
   写好 type 关系与全标注签名；**函数体一律 `todo as "..."`，一行实代码不写**。
4. 倒推 / 正推补齐整条链：`Timeframe ← Instrument ← Broker ← Desk`，
   每层提供它该有的 read / write 服务；再补 provider 原生形状、标准 `SourceBar`
   入口、直线管道与输出侧 view 边界的**位置**。
5. `gleam build` / `gleam check` 在这里是**设计探针**：它报的是缺口，不是分数。
   空 unit test 只固定 in / out types，不写断言（R42 07:39）。
6. 写实现之前，按 R43 判据**核验空架子**：对照 owner 设计逐条查用词是否准确、
   有无自造概念；把删掉的瞎编与依据记进实测（本计划 §5）。

## 3. 架子要呈现的设计（全部有裁定出处，不新增概念）

| 事实 | 依据 |
|---|---|
| `Desk` 是 top type / 根 / 中心控制室，上面不再有东西 | R42 |
| 主干链 `Desk ▸ Broker ▸ Instrument ▸ Timeframe`，每层上下两个隶属关系 | R20 / R37 |
| 身份在持有者的 Dict key：`brokers: Dict(BrokerId, Broker)`、`instruments: Dict(Symbol, Instrument)`、`timeframes: Dict(Interval, Timeframe)`；被持有者不指认持有者 | R23 / R37 |
| `Broker` 另持一组 `accounts`；`Account` 无身份字段，key 在 Broker 手里 | R33 / R36 |
| `Symbol` 是名字，不是 `Instrument` | R22 |
| `Timeframe` 带 `settings`，不带 `interval` / `symbol` / `market_type` | R23 |
| 闭集即 type，构造子写全名（`IntervalOneHour`）；线路码只在 codec | R13 / R21 |
| 标准 `SourceBar.timestamp` 是 `gleam_time.Timestamp`（unix） | R27 |
| provider 原生形状各自定义（Binance 叫 `Kline`），各自 `to_sourcebar`；标准层是唯一汇合点 | R28 |
| `bucket_ends` 是 UTC unix 秒网格；美股 09:30 + DST 是市场日历债务，等有消费方才引入 `tzif` | R29 |
| web 本地墙钟是**输出侧**投影；输入侧日历另属一层；CSV 保持 UTC | R30 |
| 流：`api provider / data sources → history + live → sourcebar_gate → databar_processing → model ↔ view`；history 与 live 是同一条流 | R33 |
| 没有 actor / scheduler / clock / poll / heartbeat；无数据则睡等；没有 replay / 倒带 / 第二套批量实现 | R33 / R38 |
| 直线：合格 `SourceBar` → `working_databar` → 全部运算/处理/决策在其中 → `working_databar_archived` → `databar_list` | R39 |
| `databar_processing` 主体是 `timeframe |> f1 |> ... |> working_databar_archived`，每步 `fn(Timeframe, ...extra) -> Timeframe`，无一步传 bar | R40 / R40-A / R41 |
| `timeframe.gleam` = `Timeframe` type + 全部相关 fn；不设独立机制模块 | R42 |
| 「叶子」特指 `YinLeaf` / `YangLeaf` | R33 |
| `Market` 与 `Broker` 双向都不隶属，否决中间层 | R36 |
| `Asset` / `Exchange` / `Market` 关系未定，按真实消费方逐个加 type，不预先造一整套关系 | R26 / R32 |
| 声控 app / web / 桌面端 / 分析决策等 type 从 `Desk` 直接或逐层展开 | R42 |

## 4. 模块清单（空架子）

倒推顺序写在各模块 `////` 里；下表只是索引，不是另一份设计。

```
src/glibe/
  desk.gleam                  Desk + BrokerId + LookupError + read/write 服务
  broker.gleam                Broker + AccountId + Account + read/write 服务
  instrument.gleam            Instrument + read/write 服务
  timeframe.gleam             Timeframe + 直线 + 管道的全部相关 fn
  config.gleam                default_config() -> Desk
  api/interval.gleam          Interval 闭集 + bucket_ends + 线路码 codec
  api/symbol.gleam            Symbol
  api/sourcebar.gleam         SourceBar + 拒绝闭集 + validate + to_databar
  databar.gleam               DataBar（只持有 type；出生属于 source）
  indicator_settings.gleam    TimeframeSettings（参数包，不是实体）
  indicator.gleam             upstream：run
  leaf.gleam                  YinLeaf / YangLeaf
  branch.gleam                DataBranch
  trading/signal.gleam        Signal 闭集
  trading/strategy.gleam      upstream：manual_signal
  binance/kline.gleam         Kline 原生态（全部线格式字段）+ to_sourcebar
  web/server.gleam            输出侧 view 边界的文档位置（不新增 type）
```

不建：`monitor.gleam`（R33 历史外来概念）、`replay`（R38）、`engine`（R42）、
`AppConfig`（旧代码把它包在 `Desk` 上面，与 R42「上面不再有东西」冲突）、
任何 provider 统一框架（R34）、`guard sh`（R44）。
