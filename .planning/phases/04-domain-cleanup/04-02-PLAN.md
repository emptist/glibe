# Phase 04 Plan 02 — Every time span is an `Interval`, not a `String`

**Plan item referenced by `////` in:** `src/glibe/api/interval.gleam`,
`src/glibe/api/rules.gleam`, `src/glibe/config.gleam`,
`src/glibe/binance/kline.gleam`.
**Rulings:** `docs/RULINGS.md` R13 (closed sets are types), R19 (docs-first),
**R21 (constructors are named in full, never wire codes)**.
The Interval closed-set item was marked *"plan first, no owner ruling needed
yet"* (`docs/RULINGS.md` R20, "明确未决、未做的事") — this is that plan.

## The fact, measured (before the change)

`src/glibe/config.gleam` held **14** per-interval limit lists in
`rules.DataRequestLimits`, all `List(#(String, Int))`:

```gleam
max_bars_per_request: [#("D1", 1000), #("H1", 1000), #("H4", 500)]
max_history_days:     [#("D1", 3650), #("H1", 730), #("H4", 1825)]
```

`"H4"` was **not a value of `glibe/api/interval.Interval`**: the type had seven
variants, the config named an eighth interval, and no compiler check could see
the mismatch. That is the exact failure the root law names — a universal
`String` standing in for a closed set, repaired by nothing at all.

`docs/REVIEW_ROUND5.md:299` records glib's settled closed set as **9** variants.
That is *corroboration*, not authority. The authority is that config already
contained a four-hour value and a `String` cannot own it.

**Historical spelling note.** The old constructor names were the short exchange
codes recorded verbatim in this block and in `docs/REVIEW_ROUND5.md`. They are
quoted here as a record of the code being replaced, not as current names.
Owner ruling R21 (2026-11-08) renames all of them; see the table in R21.

## Type-first design

1. **`Interval` becomes 9 variants**, all named in full and prefixed with the
   type name: `IntervalOneMinute`, `IntervalThreeMinute`,
   `IntervalFifteenMinute`, `IntervalThirtyMinute`, `IntervalOneHour`,
   `IntervalFourHour`, `IntervalOneDay`, `IntervalOneWeek`,
   `IntervalOneMonth`. Adding a constructor is a type change; the compiler's
   exhaustiveness check then *lists the work*: `all`, `to_string`,
   `from_string`, `bucket_ends`, and
   `binance/kline.gleam:interval_to_binance_string` must all gain an arm.
2. **Wire spellings stay at the boundary.** `"1m"`, `"3m"`, `"4h"`, `"1M"` are
   file-format / exchange vocabulary and belong *only* inside `to_string`,
   `from_string` and the Binance adapter. They are never constructor names.
3. **`DataRequestLimits` uses `Dict(Interval, Int)`** for both fields. One
   interval, one limit — identity is a typed dict key (phase-55 principle), not
   a field of a tuple and not a string to be looked up with `list.find`.
4. **Typed accessors with a typed error.** `max_bars_per_request_for` and
   `max_history_days_for` return `Result(Int, LimitError)` where `LimitError`
   is `NoBarLimit(Interval)` / `NoHistoryLimit(Interval)` — never
   `Error(String)` and never `Option` swallowing the reason.

## The two bucket-end rules (explicit engineering decisions, recorded)

- **Three-minute bucket**: ends when `minute % 3 == 0`, aligned to the hour
  (`00, 03, 06, …`). Same rule as the existing 15- and 30-minute arms.
- **Four-hour bucket**: ends when `minute == 0` **and** `hour % 4 == 0`
  (`00:00, 04:00, 08:00, …`). The hourly arm needs only the minute; the
  four-hour arm needs the hour too, so the private timestamp reader returns
  both fields instead of adding a second string splitter.
- Daily, weekly and monthly buckets stay `True` — unchanged behaviour, already
  recorded as design debt. An unreadable timestamp is still *not* a bucket end.
- **Still open, deliberately not fixed here:** `bucket_ends` takes
  `date: String`. The root-law fix is `gleam_time.Timestamp` at the ingest
  boundary (`api/sourcebar.gleam:normalize_date`); that is a boundary change
  with its own plan, not a side effect of this one. Recorded, not hidden.
