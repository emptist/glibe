# Phase 04 Plan 08 — one addressed bar, one timeframe (2026-11-09)

**Trigger.** The owner asked whether the type structure can already monitor
many instruments, each with many intervals, at the same time, and said to
continue if not. Measured answer: the static chain is complete; the **arrival
of a bar** is not.

## What is already there (measured, not assumed)

- `src/glibe/desk.gleam:74-94`: `Desk(brokers: Dict(BrokerId, Broker))` →
  `Broker(instruments: Dict(Symbol, Instrument))` →
  `Instrument(timeframes: Dict(Interval, Timeframe))`. Each `Timeframe`
  (`src/glibe/timeframe.gleam:40`) owns its settings, `working_databar`,
  `databar_list` and both growing leaves — six independent states are actually
  built in `src/glibe/config.gleam:75-101` (3 brokers × 3 instruments × 2
  intervals). Multiple instruments with multiple intervals is therefore
  already a typed, isolated fact, not a wish.
- `src/glibe/api/sourcebar.gleam:56-65`: the standard bar is one absolute
  `Timestamp` + OHLCV, with no provider identity (R27 / R28). Correct, and
  **not changed by this plan**.
- `src/glibe/binance/binance.gleam:50-54`: `fetch_klines(symbol, interval,
  limit)` fetches ONE interval's kline stream. A bar belongs to one
  `(broker, symbol, interval)`, not to "one symbol fanned out to all
  intervals". Stage F's supervised actor per instrument is recorded at
  `docs/DESIGN.md:101,261`.

## The gap (each claim carries its evidence)

- `fetch_klines` returns `List(SourceBar)`: the `symbol` / `interval` of the
  request are gone. `engine.sourcebar_gate(tf, interval, bar)`
  (`src/glibe/engine.gleam:65-69`) receives a `Timeframe` and an `Interval`
  from the caller and never checks that the bar belongs to them. A BTCUSDT bar
  can be handed to SPY's hourly `Timeframe` and every function accepts it —
  a wrong-but-well-formed value reaches the consumer with zero objections.
- There is no typed operation for "locate the addressed timeframe, advance it,
  put it back into the Desk". `test/glibe_test.gleam:367,370` performs the
  pairing by hand, in a test, for two intervals.
- `sourcebar.validate` (`src/glibe/api/sourcebar.gleam:109`) and
  `engine.sourcebar_gate` (`src/glibe/engine.gleam:69`) return
  `Result(..., String)`. A routing layer cannot say which address rejected
  which bar with a `String` (root law; R13).

## Decision — one address type, one boundary event, one pure step

- **`src/glibe/monitor.gleam`** (new module; business-domain name, singular):
  - `pub type TimeframeAddress { TimeframeAddress(broker: BrokerId,
    symbol: Symbol, interval: Interval) }`. The interval is IN the address,
    never a field of `Timeframe` (R23); the broker is needed because the same
    `Symbol` under two brokers names two different instruments (R20).
  - `pub type IncomingBar { IncomingBar(address: TimeframeAddress,
    bar: SourceBar) }`. Pairing a provider's answer with the identity of its
    request happens once, at the ingest boundary. `SourceBar` itself stays
    free of identity (R27 / R28). This is the unit a Stage F actor message or
    a replay step will carry.
  - `pub type MonitorError { AddressNotMonitored(TimeframeAddress,
    desk.LookupError) | BarRejected(TimeframeAddress, SourceBarRejection) }`.
    Errors carry the address; the lower-level `LookupError` is a FIELD, not a
    string.
  - `pub fn advance(desk: Desk, incoming: IncomingBar) ->
    Result(Desk, MonitorError)`: get broker → instrument → timeframe, run
    `sourcebar_gate`, and when a bucket closes run `databar_processing`; put
    the resulting `Timeframe` back through `put_timeframe` / `put_instrument`
    / `put_broker`. Pure, so a test and a replay see the same thing.
- **`src/glibe/api/sourcebar.gleam`**: add `SourceBarRejection`, one
  constructor per check that already exists (`NegativePrice`, `HighBelowLow`,
  `HighIsNotHighest`, `LowIsNotLowest`, `NegativeVolume`). `validate` returns
  it; `engine.sourcebar_gate` propagates it. No new check, no changed
  behaviour, no compatibility string.
- **`src/glibe/binance/binance.gleam`**: `fetch_klines`'s `symbol: String`
  becomes `Symbol` (R22). The wire query still takes a `String`, produced by
  `symbol.to_string` at that edge. Its RETURN type is not changed: the broker
  half of the address is a subscription / configuration fact, and inventing a
  provider↔broker relation here would be R26's prohibited speculation.

## Deliberately not in this plan

- No `Market` / `Asset` / `Exchange` relation and no identity typing of the
  three catalogue tables (`src/glibe/config.gleam:35-37`): R26.
- No field added to `Timeframe` or `SourceBar` (R23 / R27 / R28).
- No actor, subscription, stream, replay CLI or `gleam_otp` dependency: Stage
  F (`docs/DESIGN.md:101,261`). `advance` is the pure step such an actor would
  call; it schedules nothing.
- No fan-out of one bar to all intervals of an instrument: a kline stream is
  requested per interval. Monitoring N instruments × M intervals means N×M
  addressed `IncomingBar` values, each advancing exactly one `Timeframe`.
- No new shell guard. `gleam docs build` → `package-interface.json` carries
  this plan's link (R19).
