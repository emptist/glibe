## 3. 要做什么（设计，第二层：整个系统是一条直线）

R39 四步，没有旁门左道：

```
① 一根 SourceBar 到达
② 合格的 SourceBar 整根变成 working_databar            （sourcebar_gate）
③ 所有运算 / 处理 / 决策都在这个 working databar 中完成（databar_processing 管道）
④ working_databar_archived → databar_list，working 置 None
```

`R38`：只有两个顶层 data-treating 函数，一根 bar 到达就依次调用它们；
批次 = 这对函数跑 n 次，**不造第三个包装函数、不做 replay、不做 CLI**。

`sourcebar_gate` 的三件事（抄 glib `timeframe.gleam:192-280` 的判定，剔除
`io.println` / `clock.now()` / `period_end` / `sourcebar_buffer` / `export`）：

1. OHLC 校验：不合格 → `Error(SourceBarRejection)`，record 不变（R13，
   glibe 已有的闭集，比 glib 的 `Error` + 字符串打印更合裁定）。
2. 周期未结束 → `Ok(timeframe)`，**忽略，什么都不存**；`working_databar`
   不再是桶累加器，`fold_sourcebar` 不再被调用。
3. 周期结束 → `sourcebar.to_databar(bar, bars_listed(databar_list))` 整根
   出生，写入 `working_databar: Some(...)`。`interval` 仍由 holder 传入
   （R23 / R37），仍走 `interval.bucket_ends` 的 UTC unix 网格（R27 / R29，
   R39 偏离清单明确不质疑这两条）。

`databar_processing` 的主体（R40 / R40-A / R41）是一条管道，主语是
`Timeframe`，因为 `working_databar` 是它的 field：

```
timeframe
|> indicator      // 五条 SMA、KDJ、Bollinger，算在 working bar 上
|> leaves         // 阴阳 twin 生长；写本根 bar settle 的那一对 leaf
|> branches       // 读那一对 settled leaf，识别 / 结束 branch
|> strategy       // 决策写成 signal，写在 working bar 上
|> working_databar_archived
```

每步 `fn(Timeframe) -> Timeframe`，**没有任何参数是 bar**；所有事实从
record 里读、写回 record。设置、历史、bar 都已在 record 里，所以这五步连
额外参数都不需要（R40-A 说的「可以有无数参数」是许可，不是要求）。
加一步 = 加一个 `|>`，不改任何早先步骤。

## 6. unittests 要固定的设计意图（写完架子后再写，先列目标）

1. 合格 sourcebar → `working_databar` 是 `Some`，`idx = bars_listed`，
   OHLC 与 source 一致（整根出生，不是折叠）。
2. 不合格 → `Error(reason)`，record 原样返回。
3. 周期未结束 → record 原样，`working_databar` 不被塞进桶。
4. 同一个 `Timeframe` value 在 1h / 4h 两个 key 下判定不同（interval 由
   holder 传，R23 / R37）。
5. `databar_processing` 跑完：`databar_list` 多一根、`working_databar = None`、
   `bars_listed` +1。
6. 五个步骤各自可单独调用，首参和返回都是 `Timeframe`，bar 的 `idx` 全程不变。
7. `indicator` 后 working bar 的 `sma_tiny` 是真算出来的（首根 = close）。
8. `leaves` 写 `*_leaf_settled`；`branches` 读它 —— 不通过参数。
9. `strategy` 把 `signal` 写在 working bar 上；`Timeframe` 无 manual 字段。
10. `working_databar_archived` 不带 bar，归档的就是 record 里那根。
11. 连续 n 根 bar 走「gate → processing」n 次：list 长度 = n、idx 递增、
    每一步都不需要读上一步的签名。
