## What the time actually is

A bar happens at an **absolute instant**. Binance sends `openTime` as unix
milliseconds; other providers send a local wall-clock label that only becomes
an instant once their calendar/time-zone rule is applied. The *standard*
`SourceBar` — the reason a standard type and provider `to_sourcebar` converters
exist at all — must hold that instant, not a provider's spelling of it.

## Decision

- `SourceBar` holds `timestamp: gleam_time.Timestamp` (internally unix seconds
  + nanoseconds). The field is renamed from `date` because a `date` carrying an
  absolute instant is itself a name/entity mismatch (R22). `DataBar` likewise
  holds `timestamp`.
- **Provider adapters own `to_sourcebar` (R28).** `binance/kline.gleam`
  declares its own native `Kline` with **all twelve REST array fields** —
  `closeTime`, `quoteAssetVolume`, `numberOfTrades`, taker-buy volumes and
  `ignore` are not discarded. `decode_klines` returns `List(Kline)`;
  `to_sourcebar(kline) -> Result(SourceBar, SourceBarTimeError)` is the only
  place that converts `openTime` (unix milliseconds) and picks OHLCV for the
  standard bar. IB gets its own native type and its own converter when it
  arrives; the two are deliberately different.
- `api/sourcebar.gleam` keeps `decode_bar()` only as the adapter for one
  concrete `date`-field JSON line format; it is **not** a universal provider
  shape. Both adapters call the same `unix_timestamp` conversion helper, so a
  bad label is **rejected**, not defaulted.
- Unlabelled ISO labels are interpreted as UTC **in that adapter**, and the
  adapter says so. That is a conversion rule at the edge, not a domain-wide
  assumption baked into a utility function.
- `interval.bucket_ends(Interval, Timestamp)` tests the **unix-second grid** by
  remainder: 1h `% 3600`, 4h `% 14400`, 3m `% 180`, 15m `% 900`, 30m `% 1800`.
  No `calendar`, no offset, no `string.split`, no `clock_of` / `minute_of`.
  Day/week/month keep their existing `True` (separate debt).
- `export/csv.gleam` formats with `timestamp.to_rfc3339` at the output edge.

## Where strings live

| layer | shape |
|---|---|
| wire (JSON `date`, Binance kline element 0) | `String` / int — provider spelling |
| provider adapter (`to_sourcebar`, `decode_bar`) | convert once to `Timestamp`, or reject |
| domain (`SourceBar`, `DataBar`, engine, `bucket_ends`) | `Timestamp` only |
| output (CSV / HTML) | RFC3339 `String` |

## Behaviour changes that are corrections

- An unparseable time label is rejected at the boundary. The old `clock_of`
  fallback (`Error(Nil) -> False`, fold the bar in and wait) is the mechanism
  that let epoch-milliseconds flow through forever in the historical bug.
- A bare `"2024-01-15"` is not a bar time: an OHLC bar has a time of day.
  Tests now assert a typed rejection instead of `bucket_ends(...) == False`.
- `normalize_date` / `date_to_iso` / `epoch_ms_to_iso` / `civil_from_days` /
  `pad` and the whole `BarClock` module disappear. Handwritten civil-date
  arithmetic is replaced by `gleam_time`; the bucket test needs no calendar at
  all, only integer arithmetic on unix seconds.

## Out of scope (R26 / R29)

Exchange / market time-zone rules (including US daylight saving), markets
whose bucket grid is not UTC-aligned, `Market` types, and day/week/month
buckets still answering `True`. R29 records the owner's concrete example:
US 09:30 open is HKT 22:30 in winter and 21:30 in summer — a fixed offset
cannot be right. When a US-equity consumer appears, that plan introduces
`tzif` 2.0.0 (+ `zones` or `tzif_loader`) at the provider/market adapter and
expresses the session grid there. No constant offset, no speculative identity
typing, no `Market` invented in this plan.
