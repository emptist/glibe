## What the `date` actually is — decide this before writing code

`SourceBar.date: String` is a **provider time label**, not a point in time.
Binance sends `openTime` as epoch milliseconds; the JSON decoder and the tests
send `"2024-01-15 09:30:00"` or `"2024-01-15T09:30:00"`. What every downstream
consumer actually needs is the **wall-clock hour and minute of that label**, so
`interval.bucket_ends` can decide whether the bucket closes.

`gleam_time.Timestamp` is an absolute instant: `to_calendar` / `from_calendar`
require an UTC offset. Choosing an offset is a *domain* decision — exchange
calendars and time zones belong to market rules, which have **no type and no
consumer yet** (R26). Hard-coding UTC now would quietly decide the whole market
model inside a utility function, exactly the kind of plausible-looking wrong
direction R22 had to delete. So this plan does **not** do that.

**Decision:** name the thing that *does* exist — the provider's parsed
wall-clock reading — as `BarClock`, with fields made of `gleam_time`'s own
`calendar.Date` and `calendar.TimeOfDay`. No hand-rolled integer time type, no
private calendar arithmetic. `to_timestamp(clock, offset) -> Timestamp` is
provided explicitly so that when a market rule needs an instant, the offset is
supplied by that consumer rather than invented here. This honours the root law
("time is never a string to be split") without inventing a relation.

## Where the string is allowed to live

| layer | shape |
|---|---|
| wire (`decode_bar`, Binance kline adapter) | `String` — provider spelling |
| boundary (`bar_clock.parse`) | parse **once** into `BarClock`, or reject |
| domain (`SourceBar`, `DataBar`, `bucket_ends`, engine) | `BarClock` only |
| output (`export/csv.gleam`) | `bar_clock.to_iso` formats at the edge |

`String` never crosses into the domain, and no `string.split` on a timestamp
survives anywhere in `src/`.

## Behaviour changes that are corrections, not regressions

- A timestamp that cannot be parsed is **rejected at the boundary**, not
  silently folded into an open bucket. Today `clock_of` returns `Error(Nil)`
  and `bucket_ends` answers `False` — that fallback is the same mechanism that
  let epoch-milliseconds flow through forever in the historical bug.
- A bare `"2024-01-15"` is **not a bar time**: an OHLC bar has a time of day.
  It is rejected rather than being read as minute `0`. The two tests that
  currently assert `False` for a bare date now assert `Error(...)` from
  `parse`.
- `normalize_date` / `date_to_iso` / `epoch_ms_to_iso` / `civil_from_days` /
  `pad` disappear. `gleam_time.timestamp.to_calendar` replaces the handwritten
  Howard Hinnant algorithm — less code, official library, same answer.
