## B. 发现的问题（按严重度排序）

### B1（严重，功能缺失）交互全部丢弃——十字光标/缩放/平移是死代码
- `src/glibe/app/dashboard.gleam:238-248`：`widget_handle_event` 对一切非 chart_push
  事件返回 `None -> #(widget.UpdateState, state)`，state 原样返回。紧邻注释
  `// A cosmetic event (pointer, keyboard): consumed locally, the viewport moves, the model does not.`
  **注释说 "viewport moves"，代码从未 move viewport**——注释与代码不符。
- `src/glibe/app/dashboard.gleam:84-85`：`viewport` / `mouse` 两个字段存在，但全仓库
  对它们的写入只有 `init` 的两行（`:109-110` `default_viewport(0)` / `mouse: None`）。
  运行实证：注入 60 根 bar 后 crosshair 层仍 0 形状——`mouse` 永远是 `None`。
- `bar_stream_chart` 已提供完整交互 API：`zoom_at`(:688) / `pan_by_pixels`(:712) /
  `zoom_step`(:731) / `pan_step`(:750) / `clamp_viewport`(:680)。glibe **一个都没调用**
  （grep 全 src 无命中）。
- 参考 app `try_plushie/src/try_plushie.gleam:344-376` 把 Wheel→`zoom_at`、Press/
  Move/Release→`pan_by_pixels` + `mouse: Some(#(x,y))`、方向键→`zoom_step`/`pan_step`
  全部接线；其 README:15-17 把这套交互列为 app 的核心能力。
- **判定**：确凿。glibe 相对 try_plushie 缺了整个交互层，图是"死的"。这正是 owner 说的
  "图陋劣"的实质——不是颜色或布局，是不能缩放/平移/看十字光标。
- **修法归属**：这是 widget state 的读写，owner 是 `app/dashboard.gleam`（它已拥有
  `ChartWidgetState` 和 `widget_handle_event`，R50）。需在 dashboard 内新增事件→state
  分支，调用 bar_stream_chart 的 viewport API，并让 view 从 state.mouse 生成 crosshair
  （frame 已支持，见 dashboard `:204` 传了 state.mouse 给 frame）。
