## B. 大结构对比：唯一实质差异 = 数据如何进 UI

| | try_plushie（owner 裁决 §21） | glibe（当前） |
|---|---|---|
| 入口 | `init()` 返空 chart | `runtime.gleam:94-95` `init()` 返空 Desk + `command.none()` |
| 数据驱动 | `command.stream` 逐根 emit，从 **runtime 内部**流出（`try_plushie.gleam:191,200`） | **外部常驻 process** `live_feed.pump` → `fetch_klines` → `list.each` 逐根 `plushie.dispatch_event`（`live_feed.gleam:96,129-153`） |
| Msg 入口 | Event 内含 `Stream(StreamEvent(...))` | `message.gleam:41` Msg 只有 `MsgEye / MsgVoice / MsgSourceBarArrived`，**无 Stream 变体** |
| 每根到达 | 触发一次 view → `tree.diff` | `dispatch_event` → `handle_event` → publish → chart_push → widget state → rerender |
| 是否单 bar 更新 UI | 是（作者机制） | 是，但由**外部批量循环**驱动，不是作者机制 |

**判定**：结果等价（两图同标准对比见 C），机制不同。这是**结构差**，不是细节差。
是否把 glibe 改成 `command.stream` 内部驱动 = 待决方向（需扩 Msg + init，真改动，不在本轮擅自做）。

## D. translate 实现对比（排除"翻译写错"）

- try `fusion_view.gleam:354` `translate`：`with_id(shape.rect(...), id_string(id))` 前缀写法。
- glibe `dashboard.gleam:412` `translate`：`shape.rect(...) |> with_id(id_string(id))` pipe 写法。
- 逐分支等价：Rect / Path / Line / Text / Group / Interactive 六构造器全对应，都给**每个** shape 显式 id。⇒ 图形一致性有源码根据，不是碰巧。
